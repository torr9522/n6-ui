# Fix 01-10

## Fix 01: Rule Group List Page

- Problem: the traffic rule group first-level page mixed group rows with inline
  rule details, making navigation and maintenance unclear.
- Previous behavior: users could not treat rule groups as first-class reusable
  objects.
- Design decision: make the first-level page a rule group management page.
- Implementation: N5 Simple traffic rule UI separates group list operations from
  per-group rule maintenance.
- Affected components: `web/html/n5/simple_traffic_rule*.html`,
  `web/controller/n5/simple`, `web/service/n5/simple`.
- Commit: `a898bd14f702b75b8e9178fa6ee05f6fa10ce47d`
- Public tag: `n5-local-fix-01-rule-group-list-page`
- Regression risk: navigation and rule CRUD confusion.
- Validation: browser CRUD and regression tests.
- Final semantics: rule groups are managed as reusable entities.

## Fix 07: Deterministic Routing Priority

- Problem: creation order could decide which Simple routing rule won.
- Previous behavior: overlapping rules could behave differently depending on
  when they were created.
- Design decision: Simple execution policy uses deterministic priority.
- Implementation: generated Simple rules are sorted by semantic priority before
  Xray routing output.
- Affected components: Simple rule service and Xray routing generation.
- Commit: `a898bd14f702b75b8e9178fa6ee05f6fa10ce47d`
- Public tag: `n5-local-fix-07-deterministic-routing-priority`
- Regression risk: runtime traffic could route to the wrong egress.
- Validation: priority and creation-order independence tests.
- Final semantics:

```text
direct exact
> direct suffix
> direct keyword
> direct regexp
> custom group
> AI
> Game
> Streaming
> ALL
```

This order applies to Simple-managed execution policy. Advanced policies keep
their own `sort_order` semantics.
